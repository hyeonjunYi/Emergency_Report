# 화재조사 현장보고 — GitHub Pages 배포용

계룡소방서 현장대응단 / 작성자 기본값: 현장대응단 소방장 이현준

## 1. 최초 업로드

1. ZIP을 내려받아 압축을 풉니다. ZIP 파일 자체를 업로드하지 않습니다.
2. GitHub에 별도 저장소를 만들고 압축 안의 파일과 assets 폴더를 저장소 최상위에 업로드합니다.
3. 최상위에 index.html, editor.html, editor.js, editor.css, report.js, style.css, default.json, assets 폴더가 나란히 있어야 합니다. public 폴더나 ZIP 이름의 폴더를 한 겹 더 만들지 않습니다.
4. Add file → Upload files → Commit changes를 누릅니다. 모바일에서 업로드 메뉴가 보이지 않으면 브라우저의 데스크톱 사이트 모드를 사용합니다.
5. .nojekyll도 함께 포함했습니다. 숨김 파일이 표시되지 않는 환경에서는 GitHub의 Add file → Create new file로 .nojekyll을 만들고 내용을 한 줄 넣어 커밋할 수 있습니다.

## 2. GitHub Pages 설정

저장소 Settings → Pages → Build and deployment에서 다음과 같이 설정합니다.

| 항목 | 값 |
| --- | --- |
| Source | Deploy from a branch |
| Branch | main (파일을 올린 브랜치) |
| Folder | / (root) |

Save를 누릅니다. 배포 결과는 Actions 탭과 Settings → Pages에서 확인합니다. 완료되면 Pages에 표시된 Visit site 링크를 엽니다. 개인 계정 무료 요금제에서는 공개 저장소를 사용합니다. 공개 저장소와 Pages에 올린 보고서·사진은 외부에 공개되므로 게시 대상만 업로드합니다.

Hugo, Node, Netlify 설정과 별도의 API 키는 필요하지 않습니다. 이 묶음에는 Netlify 설정 파일이나 사용자 지정 Actions 워크플로가 없습니다. 위의 브랜치 배포 방식으로 설정합니다.

## 3. 휴대폰에서 다음 사건 작성

1. 배포된 보고서 주소의 마지막에 editor.html을 붙여 작성 화면을 엽니다. 주소 예: https://사용자명.github.io/저장소명/editor.html (실제 주소는 Pages의 Visit site 링크를 기준으로 합니다.)
2. 새 사건 시작을 누르고 이번 사건의 신고·출동·현장상황·피해현황을 입력합니다. 같은 사건을 이어 작성하려면 초안 백업을 불러옵니다.
3. 사진을 최대 8장 선택합니다. 첫 사진이 상단 대표사진입니다. 설명과 순서를 수정합니다. 새 사진은 긴 변1600px JPEG로 재저장하며 원본 위치 메타데이터는 넣지 않습니다. HEIC는 JPEG로 변환 후 선택합니다.
4. 전체 미리보기 → 게시 전 확인 체크 → 게시용 index.html 저장 순서로 진행합니다. 필요하면 생성된 index.html 다시 저장 링크를 누릅니다. 파일명이 index (1).html 등으로 저장되었다면 index.html로 바꿉니다.
5. GitHub 웹브라우저에서 저장소 최상위를 열고 Add file → Upload files로 index.html을 올려 기존 파일을 교체한 뒤 Commit changes를 누릅니다. assets 폴더나 editor 파일은 다시 올리지 않습니다.
6. GitHub Pages 배포가 완료되면 공개 보고서 주소를 새로고침합니다. 입력 화면에서 저장하는 것만으로 게시되지는 않습니다.

index.html에는 사진·스타일·보고 내용이 모두 포함됩니다. 저장소 하위 경로에도 맞도록 파일 참조는 상대경로로 구성했습니다. 휴대폰 홈 화면에 작성 화면을 추가하면 다음 출동 시 쉽게 열 수 있습니다.

## 4. 초안 보존

- 입력한 텍스트는 현재 기기의 해당 사이트 브라우저에 임시 저장합니다. 다른 기기와 자동 동기화하지 않습니다.
- 사진은 임시 저장하지 않으므로 새로고침하거나 브라우저를 닫기 전 초안 백업을 저장합니다. JSON 백업에는 사진도 포함됩니다. 백업 JSON은 공개 저장소에 올리지 않고 휴대폰에서 보관합니다.
- 공개 보고서 교체 후에도 최초 금암동 보고서 불러오기 기능은 초기 사건을 불러옵니다. 최신 사건 수정에는 해당 사건의 초안 백업을 사용합니다.
- 저장소 최상위 index.html 교체는 현재 대표 보고서 1건을 갱신합니다. 여러 사건을 별도 주소로 보관하려면 교체 전 사건별 파일명으로 저장합니다. 사건 목록 자동 생성은 없습니다.

## 5. 포함 기능과 범위

- 사용자 제공 디자인 기준을 적용한 보고서·모바일 작성 화면
- 선명한 화면 모드, 본문 바로가기, 수동 사진 전환, 인쇄/PDF
- 출동지령서 원본 및 신고자 전화번호 제외
- 작성자 기본값: 현장대응단 소방장 이현준
- 미확인 시각·피해·원인은 확인 중/조사 중 표기
- 작성 화면의 수정은 기기에서만 이루어집니다. 공개 보고서를 바꾸려면 GitHub에 로그인하여 파일을 커밋해야 합니다.
- 출동지령서 OCR, 사진의 자동 화재원인 판단, GitHub 직접 게시 버튼은 포함하지 않습니다.
- 인터넷 연결 후 작성화면을 사용합니다. 오프라인 앱은 아닙니다. 내보낸 보고서는 외부 파일 없이 열 수 있습니다.
- 내보내기는20MB 이하로 제한합니다. 실제 사용할 휴대폰에서 최초 사진 선택·다운로드를 확인합니다.
- 기관의 공식 전자정부 인증 배너를 추가하지 않았으며 접근성 인증을 주장하지 않습니다.
